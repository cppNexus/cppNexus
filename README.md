# About

I’m interested in understanding how things work, not just how to use them.

I value simplicity, control, and a clear understanding of the systems I build. I prefer explicit behavior over hidden complexity, measurable results over assumptions, and independent thinking over following conventions without questioning them.

I believe good software comes from understanding the problem, knowing the trade-offs, and taking responsibility for the result.

Less abstraction for its own sake. Fewer unnecessary dependencies. More understanding of what happens under the hood.

This is where I experiment, build things, break things, and learn.
